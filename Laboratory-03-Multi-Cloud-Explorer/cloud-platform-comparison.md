# Cloud Platform Comparison

## Introduction

After studying **Amazon Web Services (AWS), Microsoft Azure, and Google Cloud**, I learned that the three major cloud providers offer many similar services. All of them provide options for computing, storage, databases, networking, security, and application development.

Even though their services can perform similar functions, each cloud provider has different features and areas where it is stronger. Because of this, I learned that choosing a cloud platform should depend on the needs and goals of the organization.

For me, selecting a cloud provider is like choosing the right tool for a job. The best choice depends on what the company needs and what it is trying to accomplish.

## 1. Major Cloud Platform Comparison

| Category           | AWS                                           | Microsoft Azure               | Google Cloud                            |
| ------------------ | --------------------------------------------- | ----------------------------- | --------------------------------------- |
| Launch Year        | 2006                                          | 2010                          | 2008                                    |
| Compute Service    | Amazon EC2                                    | Azure Virtual Machines        | Compute Engine                          |
| Storage Service    | Amazon S3                                     | Azure Blob Storage            | Cloud Storage                           |
| Networking Service | Amazon VPC                                    | Azure Virtual Network         | Google Cloud VPC                        |
| Identity Service   | AWS IAM                                       | Microsoft Entra ID            | Cloud IAM                               |
| Main Strength      | Wide range of cloud services                  | Microsoft integration         | AI, data, and Kubernetes                |
| Best Suited For    | Startups, enterprises, and large applications | Microsoft-based organizations | AI, data, and cloud-native applications |

Although these services have similar purposes, their features, pricing, and capabilities can be different. Organizations should therefore compare the services based on their specific requirements.

## 2. Which Cloud Provider Has the Widest Range of Services?

For me, **AWS** appears to have the widest selection of cloud services. It has been providing cloud services since 2006 and has developed many tools for different computing and business requirements.

This can be helpful for organizations that want to get many different services from one provider. However, I also learned that having more services does not automatically mean AWS is the best choice. The company still needs to consider its budget, technical requirements, and existing systems.

## 3. Which Provider Works Best with Microsoft Technologies?

I would choose **Microsoft Azure** for organizations that already depend heavily on Microsoft products.

Azure works well with technologies such as **Windows Server, Microsoft 365, and Microsoft Entra ID**. Because of this, companies and schools that already use Microsoft products may find Azure easier to adopt.

For example, if a university already uses Windows Server and Microsoft 365, it could use Azure to move some of its existing systems to the cloud without completely changing its technology environment.

## 4. Which Provider Is Strong in AI and Kubernetes?

For artificial intelligence, machine learning, data processing, and Kubernetes, I would consider **Google Cloud** a strong option.

One service that stands out to me is **Google Kubernetes Engine (GKE)**. It provides a managed environment for deploying applications using Kubernetes.

However, I also learned that all three major cloud providers offer managed Kubernetes services:

* **AWS** – Amazon Elastic Kubernetes Service (EKS)
* **Microsoft Azure** – Azure Kubernetes Service (AKS)
* **Google Cloud** – Google Kubernetes Engine (GKE)

This means that companies can use Kubernetes on any of the three major platforms, although the features and management experience may differ.

## 5. Which Cloud Platform Would I Choose?

If I had to personally choose one, I would choose **Google Cloud** because I am interested in application development, artificial intelligence, and newer cloud technologies.

I like that Google Cloud provides services for computing, storage, databases, Kubernetes, and AI. These services would allow me to explore different areas of cloud computing.

However, I understand that my personal choice may not be the best choice for every organization. If I were working with a company that already used many Microsoft products, I would consider Azure. If the company needed a very large selection of cloud services, I would also consider AWS.

This taught me that a Cloud Solutions Architect should focus on the client's needs instead of choosing a provider based only on personal preference.

## 6. Equivalent Cloud Services

The three cloud providers often have services that perform similar functions but have different names.

| Service Category    | AWS        | Microsoft Azure                | Google Cloud                   |
| ------------------- | ---------- | ------------------------------ | ------------------------------ |
| Virtual Machine     | Amazon EC2 | Azure Virtual Machines         | Compute Engine                 |
| Object Storage      | Amazon S3  | Azure Blob Storage             | Cloud Storage                  |
| Identity Management | AWS IAM    | Microsoft Entra ID             | Cloud IAM                      |
| SQL Database        | Amazon RDS | Azure SQL Database             | Cloud SQL                      |
| Kubernetes          | Amazon EKS | Azure Kubernetes Service (AKS) | Google Kubernetes Engine (GKE) |

For example, **Amazon EC2, Azure Virtual Machines, and Compute Engine** are all used to provide virtual machines in the cloud.

Similarly, **Amazon S3, Azure Blob Storage, and Cloud Storage** are used for storing objects such as files, images, videos, and other types of data.

This comparison helped me understand that learning the basic purpose of a cloud service is important because different providers may use different names for similar technologies.

# My Overall Comparison

### AWS

I would describe AWS as the **"wide range of choices"** cloud provider. It offers many different services and can support various types of applications, from small projects to large enterprise systems.

### Microsoft Azure

I would describe Azure as the **"Microsoft-focused"** cloud provider. It is especially useful for organizations that already use Microsoft technologies and want to connect their existing systems to the cloud.

### Google Cloud

I would describe Google Cloud as the **"AI and modern technology"** cloud provider. I think it is particularly interesting for organizations working with artificial intelligence, machine learning, data analytics, and Kubernetes.

# Final Thoughts

After comparing AWS, Azure, and Google Cloud, I learned that there is no single cloud provider that is always the best. Each platform has its own strengths, and the right choice depends on the situation.

If I were choosing a cloud platform for a real company, I would first look at several factors, including **budget, existing technology, application requirements, number of users, customer locations, security needs, and future plans**.

After gathering this information, I would compare the available cloud services and choose the provider that best matches the organization's requirements.

The biggest lesson I learned from this activity is that being a good Cloud Solutions Architect is not about choosing the most popular cloud provider. It is about **understanding the client's needs and selecting a cloud solution that can properly support those needs**.
